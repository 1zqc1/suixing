# 随行项目三人分工方案

队长负责设备接入、接口发布和整机安全闭环。队友 A 负责感知与风险算法。队友 B 负责 Android、语音交互和独立回归。三人使用同一套[开发环境基线](开发环境与安装.md)和[验收记录](开发与验收基线.md)。

## 模块职责与接口

| 模块 | 主责与复核 | 输入 → 输出 | 边界与交付 |
|---|---|---|---|
| M1 设备与时空层 | 队长；A 验观测，B 验只读数据 | D6、双目、轮速、手柄 → ROS 2 观测、TF、诊断 | 队长负责标定、采样时间、接口版本和导出。同源序号、缺测、过期及坐标系按 [M1 v0.1](../samples/m1-handoff-v0.1/M1-接口草案.md) 保留。首轮已有合成样例，实机话题与标定待验。 |
| M2 语义感知 | A；队长上板 | 带采样时间的图像 → 类别、框、置信度与模型版本 | A 负责数据划分、训练、ONNX 回读和语义开关对照。掉线时回到几何判断。HEF 量化依赖加速卡型号和工具包确认。 |
| M3 几何风险与融合 | A；队长接收，B 复验 | D6、双目与可选语义观测 → `RiskSummary` | 输出左／直／右风险、TTC、覆盖未知、观测年龄和有效期。A 固定横穿、可通行、过期／断流用例，覆盖缺失按未知处理。 |
| M4 人机协同决策 | 队长；A 复核风险语义，B 核对提示 | `RiskSummary`、本地握持与转向意图 → `AssistRequest` | 队长负责从风险到助力请求的条件与降级。地图、语音、监护端只消费状态或提供普通提示。 |
| M5 CPU3 实时监督 | 队长；B 核对故障证据 | `AssistRequest`、风险与执行回读 → `MotionPermit` | 队长冻结 RPMsg 业务版本、会话、序号、有效期、心跳及恢复条件，复验过期、丢包和失联。现有回环证明基础通信。 |
| M6 STM32 执行与底盘 | 队长；B 做无动力复验和记录 | 有效许可与本地输入 → 两路轮端执行、制动与回读 | 队长负责驱动、电源、急停、看门狗和无人台架。分别记录制动请求、执行起效与轮端停稳。V4 概念尺寸由 B 协助核对。 |
| M7 语音与振动 | B 负责交互，队长负责安全相关振动链 | 车端状态和提示事件 → ESP32-S3 离线语音、提示音与左右振动 | B 交付词表、固件和真麦克风记录。队长验危险振动优先级、链路异常及制动隔离。语音失效时由本地安全链继续保护。 |
| M8 Android 与地图 | B；队长提供只读车况，A 提供风险样例 | 手机 GPS 或 DEMO、只读车况 → 实时地图、历史、导出 | B 负责权限与隐私、WGS84 点轨迹、百度底图渲染和回放。车辆数据接入保持只读，事件传输、时钟对齐和授权共享需另行联调。 |
| M9 测试与证据 | B 汇总；队长提供板端原始记录，A 提供算法对照 | 录包、版本、日志和测试结果 → 可复跑验收记录 | B 维护回归用例、断网与异常记录及演示步骤。队长维护底层日志与原始录包，采集和留证须与实时链解耦。 |

## A、B 的交付顺序

| 任务 | 可交接结果与通过条件 |
|---|---|
| A1 数据与标定 | 按采样时间配对左右图，核对 D6、标定和 TF。导出版本化清单和预处理命令，缺帧、倒序及无效值有标记，训练和验证按场景分组。 |
| A2 几何风险 | 先在短录包、图像和 JSONL 中实现占用、接近趋势和左／直／右扫掠风险。提交正常、危险、过期或断流样例与预期输出。 |
| A3 YOLOv8n 与 ONNX | 提交训练配置、类别、数据版本、验证结果和 ONNX 哈希，队长能按同一命令复验。 |
| A4 融合与消融 | 同一场景比较几何、几何加语义、语义掉线三种工况，交付带时间域的事件样例。 |
| B1 地图与模拟轨迹 | 已实现模拟路线、开始／结束及地图跟随。复验隐私拒绝、未配置 AK、底图失败和底图正常四条路径。 |
| B2 真机 GPS 与历史 | 已实现逐点追加、本地数据库、离线记录与回放、JSONL 导出。户外记录时核对点序号、时间差和分段。补测未缓存区域底图、长时后台与续航。 |
| B3 只读状态与共享 | 三份 M1 车况已在 App 接通。下阶段由队长发布实车只读协议，A 提供风险样例，B 复验断流、事件时间和授权撤销。 |
| B4 ESP-SR 与提示 | 样例已能构建。使用 ESP32-S3 实板和实际麦克风验证命令词、噪声表现与交互优先级。 |
| B5 独立复验与展示 | 按同一代码和数据版本复跑 A 的用例与队长的接口样例，保存预期、实测、复测结论和演示步骤。 |

## 联调与交接

1. **样本对齐。** 队长提供同一采集段的录包、导出图像与 JSONL、TF、标定和模拟车况。A 验证采样及几何输入，B 验证状态展示。首轮以仓库内的合成包为公共测试输入。
2. **几何与台架。** A 提供 `RiskSummary`、有效期用例及复现命令。队长在 Jammy 重编并上无人台架，记录 CPU3 接收、STM32 执行和故障恢复。B 独立复验，按[双赛总纲](随行-双赛冲击国一总纲V1-2026-11-19.md)的安全门禁决定是否进入有人动态测试。
3. **交互与证据。** B 提交 APK 版本、ESP-SR 构建记录、断网／拒绝授权用例与演示记录。车端时间和手机时间各自保留。需要在地图上标注事件时，由队长与 B 明确同步方式和误差界限，再用同一场景验收。

队长主机负责 Jammy、长录包、交叉编译及正式集成。A 的 16 GB 内存和 RTX 5060 8 GB 用于短样本和分批训练，长录包由队长执行。B 的 16 GB 内存和 RTX 4050 6 GB 用于 Windows 下 Android 和 ESP-IDF，优先手机真机调试。Ubuntu 24.04 克隆用于通用开发与轻量回归。
