## 1. 项目概述

### 1.1 定位

一台桌面级具身移动平台，能在有人活动的空间里**听懂指令、看得懂人、走得安全**。三个可演示能力：

| 能力 | 具体表现 | 技术支撑 |
|---|---|---|
| 听得懂 | "去红色锥桶""跟着我""回原位" | 模板 + 实体槽位解析，映射到检测类别 |
| 看得懂人 | 识别人、估距离、判断是否挡路 | 视觉检测 + 单目测距 + 追踪 |
| 走得安全 | 按人机距离动态限速、受控停止、断使能 | 安全包络 + 双通道校验 + 硬件急停 |

### 1.2 核心机制

**一句话：规划域决定"往哪走"，安全包络决定"能走多快"。**

规划域输出期望速度 `(v, ω)`，实时域按人机距离独立计算允许上限 `v_max`，执行 `min(v, v_max)`。规划域无法修改包络参数——这是架构级的约束，不是配置项。

三个时间尺度：

| 环节 | 周期 | 运行位置 | 抖动要求 |
|---|---|---|---|
| 规划 | 100 ms（10 Hz） | 规划域 | 无严格要求 |
| 控制 | 1 ms（1 kHz） | 实时域 | P99 ≤10 µs |
| 驱动 | 50 µs（20 kHz PWM） | 执行域 | 硬件保证 |

## 2. 系统组成

### 2.1 总体架构

```
感知输入 ──┐
           ├─→ 规划域（Linux 3 核）──期望速度──→ 实时域（CPU3）──PWM──→ 执行域（F103）──→ 电机
指令输入 ──┘                                      ↑                        │
                                                 └────编码器实测────────────┘
                                         执行域 ──只读遥测──→ 观测域（ESP32-S3）
```

### 2.2 模块职责

| 模块 | 硬件 | 职责（唯一真源） | 明确不做 |
|---|---|---|---|
| 规划域 | 飞腾派 CPU0–2 | 图像采集、目标检测、追踪、代价场、局部规划、指令解析、日志落盘 | 不直接控制电机；不参与 1 kHz 环 |
| 实时域 | 飞腾派 CPU3 | 安全包络、取小执行、速度环给定、心跳监控、故障锁存 | 不做视觉；不接受未经校验的速度 |
| 执行域 | STM32F103ZET6 | 双电机 PWM、编码器解码、电流采样、急停关断、使能继电器 | 不自行决定速度；不接收观测域数据 |
| 观测域 | ESP32-S3 | 1 Hz 遥测、本地看板、断网缓存、故障快照 | **永不参与控制或授权**，单向只读 |
| 感知 | USB 相机 + ToF + IMU | 视觉、近距障碍、航向与打滑 | — |
| 机构 | 差速底盘 + 双电机 + 舵机（可选） | 运动执行 | — |

### 2.3 关键接口

| 接口 | 物理 | 速率 | 方向 | 说明 |
|---|---|---|---|---|
| 规划域 ↔ 实时域 | OpenAMP / RPMsg | — | 双向 | 期望速度 + 状态回报 |
| 实时域 ↔ 执行域 | UART1（PA9/PA10） | 115200 8N1 | 双向 | 速度给定 + 编码器/状态 |
| 执行域 → 观测域 | UART3（PB10/PB11） | 115200 8N1 | 单向 | 遥测帧，类型白名单隔离 |
| 规划域 ← 相机 | USB 3.0 UVC | — | 单向 | V4L2 取流 |
| 执行域 ← 急停 | GPIO / BKIN | — | 单向 | 硬件关断 PWM，不经 CPU |

> 端口类型白名单：UART1 收到遥测帧类型一律丢弃，UART3 收到控制帧类型一律丢弃，接错线也不会互相注入。

### 2.4 安全状态分级

| 级别 | 触发条件 | 行为 | 恢复 |
|---|---|---|---|
| **S0 正常** | 全链路健康 | 按 min(规划, 包络) 行驶 | — |
| **S1 降速** | 人进入 1.2 m；规划超时 300 ms | 限速 0.15 m/s，声光提示 | 条件解除自动 |
| **S2 受控停止** | 人 <0.5 m；障碍 <0.3 m；电池欠压 | 减速到零，**保持使能** | 人工确认或条件解除 |
| **S3 断使能** | 急停；实测超速 10% 持续 100 ms；心跳丢失 500 ms | 断开使能 + 下桥臂制动 | 人工复位 |

### 4.3 安装步骤

#### 4.3.1 飞腾派（规划域）

```bash
# 1. 基础环境（首次）
sudo apt update && sudo apt install -y build-essential cmake git \
    libopencv-dev v4l-utils i2c-tools can-utils

# 2. 编译 ncnn（板端原生编译，线程数固定 2）
git clone https://github.com/Tencent/ncnn.git && cd ncnn
git checkout 2c6176e && mkdir build && cd build
cmake -DCMAKE_BUILD_TYPE=Release -DNCNN_OPENMP=ON -DNCNN_VULKAN=OFF ..
make -j2 && sudo make install

# 3. 部署应用
scp -r rover_app/ user@<板卡IP>:~/
```

> 线程数固定 2（2 大核 + 2 小核，开 4 线程反而更慢）。

#### 4.3.2 开发主机（交叉编译环境）

```bash
# 1. 工具链（解压即用，无需安装）
mkdir -p ~/opt && tar -xf xpack-arm-none-eabi-gcc-13.3.1.tar.gz -C ~/opt

# 2. SDK 与 standalone 子模块
git clone https://gitee.com/phytium_embedded/phytium-free-rtos-sdk.git
cd phytium-free-rtos-sdk
git clone https://gitee.com/phytium_embedded/phytium-standalone-sdk.git standalone
cd standalone && git checkout bb89bb66 && cd ..

# 3. 环境变量
export AARCH64_CROSS_PATH=$HOME/opt/xpack-arm-none-eabi-gcc-13.3.1

# 4. 构建（配置文件名 ≠ make 目标名）
cp configs/openamp_for_linux.config sdkconfig
make config_pe2204_phytiumpi_aarch64
make USR_BOOT_DIR=$HOME/work/out image
```

**已知坑**：`USR_BOOT_DIR` 默认指向作者 WSL 路径 `/mnt/d/tftpboot`，必须显式覆盖；`sdkconfig` 不能删，否则 Kconfig 解析失败。

#### 4.3.3 执行域（F103）

1. CubeMX 新建工程，选 STM32F103ZETx；
2. 配置时钟 8 MHz HSE ×9 = 72 MHz；
3. 外设：TIM1/TIM8（PWM 20 kHz）、TIM2/TIM3（编码器）、USART1/2/3、ADC1（2 通道）、I2C1；
4. 生成 Makefile 或 CubeIDE 工程，实现 `ports/stm32f1/` 五个钩子；
5. ST-Link 烧录。

> 关闭 JTAG 才能释放 PB3/PB4/PA15；DMA 通道按 F1 固定映射配置。

#### 4.3.4 观测域（ESP32-S3）

```bash
idf.py set-target esp32s3
idf.py menuconfig        # 配置 WiFi SSID/密码、UART 波特率
idf.py build flash monitor
```

| 串口号 | 会随 USB 口变化 | 每次先枚举确认，不要写死 COM 号 |

### 5.3 网络与端口

| 项 | 值 | 说明 |
|---|---|---|
| 飞腾派 IP | `board.local` | 手机热点分配，**随时可能变** |
| 虚拟机 IP | `192.168.146.129` | VMware NAT 固定 |
| 有线网口 | 左 eth1、右 eth0 | 插线走 DHCP |
| SSH | 使用现场已配置的账号和密钥 | 由设备负责人管理 |
| Web 看板 | 8080 | **待确认**（规划域服务端口） |
| MQTT（可选） | 1883 | 仅在启用边缘网关时开放 |
| ESP32 看板 | 80 | 局域网内访问 |
| 串口 | 115200 8N1 | 调试口 J2 的 8/10/12 脚 |

**已知网络问题**：

- 飞腾派开机可能自动回连校园网（不同网段），需串口登录后 `nmcli connection up <热点名>` 切回；
- 校园网未过 Portal 认证时，`apt update` 会报证书不受信任；
- 板子访问 `raw.githubusercontent.com` 常失败，大文件建议在电脑下载后 `scp` 上传。

### 5.4 权限设置

| 场景 | 配置 | 说明 |
|---|---|---|
| 飞腾派登录 | 使用设备负责人配置的账号 |
| sudo | `user` 加入 sudoers | 部署与系统配置需要 |
| 串口设备 | 用户加入 `dialout` 组 | `/dev/ttyUSB0`、`/dev/ttyAMA2` |
| 应用服务 | systemd 单元 `rover-app.service` | 开机自启 + 崩溃重启 |
| 实时域加载 | `sudo sh -c 'echo start > /sys/class/remoteproc/remoteproc0/state'` | 需 root |
| ST-Link（Linux） | udev 规则授予 `plugdev` | **待确认** |
| Windows 串口 | 设备管理器确认无感叹号 | CH340 驱动缺失时会出现 |

### 5.5 时间与时钟

| 项 | 说明 |
|---|---|
| 飞腾派无 RTC 电池 | 断电即回退，`apt` 与日志时间会错乱 |
| 处理 | 开机 `sudo date -s "..."` + `sudo hwclock -w`，或加装纽扣电池 |
| 追溯口径 | **不用墙钟**，用单调时钟 + 工件/轨迹序号做主键 |

## 7. 附录

### 7.1 常用命令

```bash
# 查看从核状态
cat /sys/class/remoteproc/remoteproc0/state

# 启动从核
sudo sh -c 'echo start > /sys/class/remoteproc/remoteproc0/state'

# 校准时间
sudo date -s "2026-11-16 18:00:00" && sudo hwclock -w

# 查串口
ls /dev/ttyUSB* /dev/ttyAMA*

# 摄像头取流测试
v4l2-ctl --list-devices
v4l2-ctl -d /dev/video0 --list-formats-ext

# 查看温度
cat /sys/class/thermal/thermal_zone0/temp

# 服务状态
systemctl status rover-app
journalctl -u rover-app -f
```

### 7.2 引脚分配（执行域，建议值）

| 功能 | 引脚 | 复用 | 备注 |
|---|---|---|---|
| 电机 A PWM | PC6 | TIM8_CH1 | 与旧方案一致 |
| 电机 B PWM | PC7 | TIM8_CH2 | 与旧方案一致 |
| 编码器 A | PA0/PA1 | TIM2_CH1/CH2 | 编码器模式 |
| 编码器 B | PA6/PA7 | TIM3_CH1/CH2 | 编码器模式 |
| 规划域串口 | PA9/PA10 | USART1 | 经 CH340 或直连 |
| 遥测串口 | PB10/PB11 | USART3 | 单向到 ESP32 |
| 电流采样 | PC0/PC1 | ADC1_IN10/IN11 | **待确认**与原理图核对 |
| 急停输入 | PB0 | GPIO / BKIN | 常闭，高有效 |
| 使能继电器 | PB1 | GPIO 输出 | 与急停串联 |

> 上表为建议分配，落地前必须与实物原理图逐脚复核（历史教训：模块丝印与网络名不一致）。
