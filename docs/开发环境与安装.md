## Android 与百度地图

1. 从 [Android Studio 官方入口](https://developer.android.com/studio) 安装支持 API 36 的版本。在 SDK Manager 选择 Android 16 API 36、Build Tools 36.0.0 和 Platform-Tools。同轮 Windows 主机的 Platform-Tools 为 37.0.3。安装 JDK 21，并在 IDE 的 **Gradle JDK** 和终端 `JAVA_HOME` 指向它。
2. 在 Android Studio 打开 `android/suixing-app`，通过 `ANDROID_HOME` 或模块根目录的 `local.properties` 配置 SDK。首次 Gradle 同步需要可访问 Gradle 分发站、Google Maven、Maven Central 和 Gradle Plugin Portal。成功缓存后可使用 `--offline`。[AGP 兼容信息](https://developer.android.com/build/releases/past-releases/agp-8-9-0-release-notes)
3. 使用 Android 类型 AK，在百度控制台绑定 `org.suixing.app` 和实际 APK 签名 SHA-1。将 AK 放在 Git 忽略的 `local.properties`（`baidu.map.ak=...`）或 `BAIDU_MAP_AK`。Windows 路径可写作 `sdk.dir=D\:/Android/SDK`。第一轮可用未配置 AK 的轨迹示意图复验记录和回放。[应用运行与回归](../android/suixing-app/README.md) · [百度 AK 指南](https://lbs.baidu.com/docs/guide?title=android-guide/create-project/ak)
4. 手机启用 USB 调试并在设备上确认授权，以 `adb devices -l` 核对设备。需要自动化回归时，另装 Android Emulator 和 API 36 x86_64 系统镜像。Windows 使用当前 Studio 支持的 Emulator，WHPX 按系统设置启用并重启后生效。SDK 下载断流、缓存、真机与地图排障见[仓库内 Skill](../.agents/skills/debugging-suixing-android/SKILL.md)。

从应用目录执行以下命令。Linux 的命令行构建使用 `./gradlew`，装配依赖的 SDK 版本相同，团队验收记录使用 Windows。

```powershell
.\Build.cmd testDebugUnitTest lintDebug assembleDebug assembleDebugAndroidTest
adb devices -l
```

## Ubuntu、Humble 与飞腾工具链

Ubuntu 24.04 克隆用于验包、Python 回放和轻量开发。队长在独立的 Ubuntu 22.04 Jammy x86_64 虚拟机完成 Humble 构建和录包回放，安装时需要可用的 APT 源、`curl`、`git` 和 sudo。以下命令从仓库根目录运行。安装脚本会配置 ROS APT 源并创建本机开发账户 `suixing`，rosdep 默认缓存初始于该账户。需要图形化验证时安装 `ros-humble-rviz2`。[ROS 2 Humble 的 Ubuntu 安装文档](https://docs.ros.org/en/humble/Installation/Ubuntu-Install-Debs.html)

```bash
sudo bash dev-env/setup-humble.sh
sudo apt install ros-humble-rosbag2-storage-default-plugins ros-humble-rviz2
source /opt/ros/humble/setup.bash
rosdep update --rosdistro humble
bash dev-env/verify-humble.sh
```

飞腾交叉工具链在上述 x86_64 Jammy 环境中安装。Linux 交叉编译脚本使用 USTC Ubuntu 镜像，需要访问该镜像。裸机安装脚本从 Arm 下载工具链，默认解压到 `~/opt/arm-gcc`。按验收提交将 [FreeRTOS SDK](https://gitee.com/phytium_embedded/phytium-free-rtos-sdk) 放在 `~/work/phytium-free-rtos-sdk`，其配套 standalone SDK 放在目录下的 `standalone/`，再运行构建。

```bash
sudo bash dev-env/setup-cross-linux.sh
bash dev-env/setup-cross-baremetal.sh
bash dev-env/build-phytium-openamp.sh
```

Linux AArch64 程序与 CPU3 ELF 分别使用对应编译器。产物在 `dev-env/phytium-build/`。上板之前核对 `verify.txt`、镜像/BSP 和 CPU3 的固件装载配置，保留可回退介质。通用 RPMsg 回环仅覆盖基础通信。业务端点、时效检查与 STM32 执行回读由队长在独立台架验收。

## YOLO 与加速卡

安装 Python 3.11 x64 和支持 CUDA 12.8 的 NVIDIA 驱动。依赖清单含 CUDA 12.8 对应的 PyTorch wheel。将[官方 yolov8n.pt](https://github.com/ultralytics/assets/releases/download/v8.3.0/yolov8n.pt) 放在 `dev-env/yolo-baseline/` 后，在仓库根目录执行下列命令。验证脚本会校验权重并比较 PyTorch GPU 推理和 ONNX Runtime CPU 回读。

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r dev-env/yolo-baseline/requirements-win-cu128.txt
.\.venv\Scripts\python.exe dev-env/tests/verify-yolo.py
```

Hailo 的 DFC、Model Zoo、HailoRT 和 PCIe 驱动按实际卡型与板端 BSP 单独配套。卡型与版本尚待冻结。A 负责 ONNX、量化数据及 HEF 产物，队长负责 ARM64 驱动与上板复验。采纳的第三方包、模型及数据集随交付记录来源和许可证。

## ESP32-S3、STM32 与开发辅助工具

- **ESP-SR。** 安装 ESP-IDF 5.4.4 及其工具、Python 环境和 USB 驱动。在 ESP-IDF 终端进入 `dev-env/tests/esp-sr-baseline`，运行 `idf.py -D IDF_TARGET=esp32s3 build` 和 `python verify-artifacts.py`。首次构建依赖 Espressif 组件仓库。固件、分区与模型镜像通过后，由 B 按实际板型及串口设置验证音频和命令词。[ESP-IDF v5.4.4 安装](https://docs.espressif.com/projects/esp-idf/en/v5.4.4/esp32s3/get-started/index.html)
- **STM32。** 由队长通过 ST 官方发行渠道安装 [STM32CubeIDE](https://www.st.com/en/development-tools/stm32cubeide.html)、[STM32CubeProgrammer](https://www.st.com/en/development-tools/stm32cubeprog.html) 与 [STM32CubeC5](https://github.com/STMicroelectronics/STM32CubeC5)。先在 CubeIDE 确认目标器件、调试器连接和 M6 台架接口，再在验收记录锁定版本。
- **CAD。** STEP 和重建入口见 [V4 概念装配](rover-v1-20261116/cad-v4-two-drive/README.md)。SolidWorks 原生自动化需要 Windows 下已授权的 SolidWorks、Python 3.10 x64、`pywin32==312`、匹配的零件／装配模板及会话 COM 权限。它是本地建模辅助工具，交接以可打开的 STEP 和几何报告为准。
- **Codex 和 MCP。** 项目可直接通过 Git、Gradle、ADB 和 Python 复验。可选手机界面自动化实测使用 Node.js 24.14.1 和 `@mobilenext/mobile-mcp@1.0.18`，需要 SDK、可用的 ADB 和本机 stdio 配置。Skills、安装来源和局限见 [Android GitHub 工具记录](android-github-tooling.md)。代码提交不依赖某个 Codex 桌面发行版。
