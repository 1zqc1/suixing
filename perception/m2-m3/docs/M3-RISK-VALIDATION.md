# M3 风险输出与实采验收

## TTC 字段

JSON 风险摘要保留 `ttc_s`，表示直行候选轨迹的 TTC 区间。风险节点启用 `publish_directional_ttc:=true` 时，摘要额外提供 `ttc_by_direction_s`，含 `left`、`straight`、`right`。每个值都是相对摘要生成时刻的秒数区间 `[lower, upper]` 或 `null`，其中 `straight` 与 `ttc_s` 一致。无预测碰撞或缺少计算条件时返回 `null`，下游还应结合对应的风险等级和覆盖状态。已处在车身余量内的障碍可直接产生 `[0, 0]`。

算法沿候选轨迹按固定步长扫掠车体，加上车体与障碍在步长内的最大相对位移作为余量，并从估计窗口扣除证据年龄。因此区间描述算法首次触发风险的时段。验收时用独立标注或测量对照，并记录提前预警与漏报。64 字节 SXR1 v1 继续编码原有的直行 TTC，可用主机解码器和队长的 CPU3 端口核对。

两个输入源均新鲜且采样差不超过 40 ms 时，M3 才使用自由空间证据证明 `CLEAR`。默认每个探测点允许其中一个传感器证明覆盖。配置 `require_stereo_coverage=True` 的算法调用对每个探测点要求两个传感器都有证据。单源或未对齐时仍可用障碍证据报风险，缺少覆盖的方向保持 `UNKNOWN`。

## 录制和提供的数据

- ROS 2 同一时钟域录包，包含 D6 扫描、左右图像、对应 `CameraInfo`、`/odom`、`/tf`、`/tf_static`、风险 JSON 及二进制话题。启用语义时一并录制 `/suixing/detections_2d`（或 JSON 调试检测）、`/suixing/detection_model` 和 `/suixing/scene_objects`。保留采样时间戳和播放所需的 QoS。
- 记录车体尺寸、轮速和速度范围、左／直／右实际曲率及制动距离。双目和雷达安装外参用实测配置。
- 每个场景提供试次编号、可对齐的开始和结束时间、车速、目标类别与运动方向、目标相对距离或独立位置轨迹、预计受影响的方向。如果有停止或接触时刻也一并提供，并记录真值的获取方法及误差。
- 先用隔离驱动输出的台架验证收包和超时，再用受控场地低速采集空路、左侧、正前、右侧、横穿、近地障碍、短时遮挡和断流。每种场景保留多次采集。用这些试次测风险方向、TTC 误差、持续 `UNKNOWN`、漏警和误警，并记录采集到风险输出及到 CPU3 回执的延迟。

## 本地几何回归

```bash
export PYTHONPATH="$PWD/ros_ws/src/suixing_risk"
python3 -m unittest discover -s tests -p test_geometry.py -v
```

回归使用合成障碍和已知车速，验证空路、左／直／右单侧风险、运动目标的自车运动补偿、证据年龄、对齐边界、精确到期和未修改的 64 字节线数据。
