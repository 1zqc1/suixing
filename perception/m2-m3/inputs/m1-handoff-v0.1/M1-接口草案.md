# M1 接口草案 v0.1

本草案用于随行第一轮接口联调。队长提供传感话题、统一的观测数据格式和车况样例。A 用观测数据开发几何风险节点，B 用车况样例开发只读状态页和回归用例。下列话题名和字段供三人首轮对接，设备参数以实测和共同确认的结果为准。

## ROS 2 Humble 传感入口

| 输入或用途 | 拟用话题 | 消息类型 | 坐标系或说明 |
|---|---|---|---|
| D6 平面扫描 | `/d6/scan` | `sensor_msgs/msg/LaserScan` | `d6_link`。距离用米，角度用弧度。 |
| 左、右原始图像 | `/stereo/left/image_raw`、`/stereo/right/image_raw` | `sensor_msgs/msg/Image` | 分别使用 `stereo_left_optical_frame`、`stereo_right_optical_frame`。 |
| 左、右相机参数 | `/stereo/left/camera_info`、`/stereo/right/camera_info` | `sensor_msgs/msg/CameraInfo` | 每侧与对应图像的时间戳、坐标系和分辨率匹配。 |
| 安装坐标关系 | `/tf_static` | `tf2_msgs/msg/TFMessage` | 从 `base_link` 可到达雷达坐标系和两侧光学坐标系。安装外参由实测或标定给出。 |
| 采集健康状态 | `/diagnostics` | `diagnostic_msgs/msg/DiagnosticArray` | 区分在线、离线、冻结和时间戳异常。 |

`base_link` 以车身为参考，x 向前、y 向左、z 向上。相机光学坐标系的 x 向图像右侧、y 向图像下方、z 向前。雷达的 `header.stamp` 对应一帧扫描的首条光束，图像的 `header.stamp` 对应图像采集时刻。采集时刻只能估算时，在交接数据中标明时间来源。[LaserScan 消息](https://github.com/ros2/common_interfaces/blob/humble/sensor_msgs/msg/LaserScan.msg) · [Image 消息](https://github.com/ros2/common_interfaces/blob/humble/sensor_msgs/msg/Image.msg)

轮速和手柄先按总纲保留接口。STM32 的实际开发板、编码器与手柄输入确认后，再冻结话题、频率和字段。

## 给 A 的观测与风险接口

导出的 JSONL 每行对应一条观测。同一个录包中的图像、雷达数据和标定资料随交接版本提供，图像在 `payload` 中以数据目录下的相对路径引用。导出的单个无效或缺失读数用 `null` 表达，整条观测的质量及必要 TF 的可用性通过 `quality` 表达。

| 字段 | 第一版约定 |
|---|---|
| `schema_version`、`source` | 版本为字符串 `"0.1"`。来源为 `d6`、`stereo_left` 或 `stereo_right`。 |
| `data_origin` | `mock` 表示模拟，`recorded` 表示实采。`source` 仍用来表示是哪一路传感器。 |
| `session_id`、`seq` | `session_id` 标识一次采集会话。`seq` 是非负整数，在同一来源和会话中递增。 |
| `stamp_ns`、`stamp_source` | 采样时间以 ROS 时钟域的纳秒十进制字符串表示。时间来源填 `device` 或 `receive_estimate`。 |
| `received_ros_ns`、`received_monotonic_ns` | 收包时的 ROS 时钟和接收端单调时钟，均以纳秒十进制字符串表示。缺失时填 `null`。只能在同一时钟域和同一会话中比较时间。 |
| `frame_id`、`quality` | `frame_id` 与 ROS 消息一致。质量为 `valid`、`unknown` 或 `invalid`。 |
| `valid_for_ms` | 正整数毫秒。设备上限待实测时填 `null`，此时对新鲜度的判定为未知。 |
| `payload` | 雷达保留角度参数、量程和距离序列。图像保留相对路径、编码和分辨率，对应相机参数随样本提供。 |

回放时用采样时间对齐观测。实时数据的年龄由采集到收包的时间差和收包后的停留时间组成。前者要求采集与收包的 ROS 时间可对齐，后者用接收端单调时钟计算。采集时刻仅为接收估算、时钟跳变或时钟域无法对齐时，采集新鲜度标记为未知。双目的同步方式随样本注明，配对容差在实际取流后确定。

### D6 模拟扫描样本

`samples/sensors/d6-scan.mock.jsonl` 可逐行解析。三行的 `source` 都是 `d6`，`data_origin` 都是 `mock`，`frame_id` 是 `d6_link`。样本用 5 条光束、合成时钟和 100 ms 有效期演示解析与边界处理。量程、扫描角和有效期将在真机采集后另行确认。

雷达 `payload` 使用 `angle_min_rad`、`angle_max_rad`、`angle_increment_rad`、`range_min_m`、`range_max_m` 和 `ranges_m`。距离序列的第 i 项对应 `angle_min_rad + i × angle_increment_rad`，索引从 0 开始。缺测点用 JSON 的 `null` 保留原角度位置。

| `seq` | 场景 | 收包时年龄 | 预期处理 |
|---|---|---:|---|
| 1 | 正常扫描 | 20 ms | `valid`，可读入全部测距值。 |
| 2 | 部分测距缺失 | 30 ms | `unknown`。可读取其余光束，缺测方向按未知处理。 |
| 3 | 到达时已过期 | 200 ms | `invalid`。解析用于报告过期，融合按无效数据处理。 |

三行的收包年龄用 `(int(received_ros_ns) - int(stamp_ns)) / 1_000_000` 得到，单位毫秒。样本年龄达到有效期即视为过期。

A 的 `RiskSummary` 首轮对接字段如下。

| 字段 | 草案约定 |
|---|---|
| `session_id`、`seq` | 风险节点会话和会话内递增整数序号。 |
| `risk` | 对象包含 `left`、`straight`、`right`，各取 `CLEAR`、`CAUTION`、`DANGER` 或 `UNKNOWN`。 |
| `ttc_s` | 预计碰撞时间区间，按秒表示为 `[最早, 最晚]`，未知填 `null`。 |
| `unknown_region` | 布尔值，标记当前判断范围内是否存在未知区。 |
| `source_age_ms`、`valid_for_ms` | 来源年龄与本摘要的有效期，单位毫秒。无法确定时填 `null`，由接收方按未知处理。 |
| `suggested_speed_limit_mps` | 建议限速，单位米每秒，缺失时填 `null`。 |

首次联调准备正常和过期两条样例，由 CPU3 业务协议验证接收或拒绝。固件字段宽度、校验和与生效条件在该协议的板端验收中确定。

## 给 B 的只读车况 JSON

三个文件位于 `samples/vehicle-status/`。示例都标有 `source: "mock"`，各自代表一个独立场景。`sample_time_utc` 是用于显示的合成 UTC 时间。

| 文件 | 系统状态 | 预期页面显示 |
|---|---|---|
| `normal.json` | `READY` | 待机，两种传感器在线，当前无运动许可。 |
| `sensor-offline.json` | `FAULT_SAFE` | D6 离线，已请求制动，制动回读未知。 |
| `brake-latched.json` | `BRAKE_LATCHED` | 保持制动，示例有制动已施加的反馈。 |

`motion_permitted`、`estop_active`、`brake_requested` 为布尔值。`brake_feedback` 表示执行回读，取 `RELEASED`、`APPLIED` 或 `UNKNOWN`。传感器健康状态存于 `sensors` 对象，`reason_code` 用于展示当前状态原因，三份样例分别使用 `NONE`、`D6_OFFLINE`、`HAZARD`。车况 JSON 供只读显示和回归测试使用。

## 首轮验收

1. A 能读入同一时段的观测，按采样时间和 `frame_id` 对齐数据。
2. B 能读入三个 JSON，显示对应状态，并区分制动请求和确认回读。
3. 队长在 Jammy 用 Humble 回放首段参考录包，在 RViz2 检查 `base_link` 下的扫描和 TF。实物数据交接附上提交号、数据版本、来源、复现命令和结果。
